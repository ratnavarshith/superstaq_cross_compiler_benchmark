# SuperstaQ Cross-Compiler Benchmark

## Results

The benchmark compiled n in {4, 6, 8} qubits across four circuit families through
two compilers:

- **Qiskit opt-3 / SABRE** targeting FakeSherbrooke (127-qubit heavy-hex, ECR native gates)
- **SuperstaQ `cq_sqale_simulator`** (Infleqtion Sqale neutral-atom, CZ native gates,
  all-to-all connectivity via atom shuttling)

**Coverage:** The SuperstaQ free-tier account ran out of credits partway through the
sweep. Qiskit results cover all 45 circuits across n = {4, 6, 8}. SuperstaQ results
cover all circuits at n=4 (15/15) and three QAOA circuits at n=6 (line, ring, complete
only). No SuperstaQ data was collected at n=8. The headline finding holds on the data
collected.

### Finding: the neutral-atom advantage is topology-conditional

SuperstaQ does **not** universally outperform Qiskit. The outcome depends on whether
the circuit's connectivity pattern conflicts with heavy-hex topology.

| Condition | Winner | Example |
|---|---|---|
| Ring-topology QAOA (n=4) | **SuperstaQ** (27% lower) | Qiskit 2.75x vs SuperstaQ 2.00x |
| Ring-topology QAOA (n=6) | **SuperstaQ** (37% lower) | Qiskit 3.17x vs SuperstaQ 2.00x |
| Line-topology QAOA (n=4, 6) | Tie | Both compilers reach 2.00x |
| ER-topology QAOA (n=4, median of 5 seeds) | Tie | Both 2.00x median |
| Complete-graph QAOA (n=4, 6) | Near-tie (within 7%) | Both ~3.0-3.3x |
| QFT (n=4) | **Qiskit** (28% lower) | Qiskit 2.25x vs SuperstaQ 3.13x |
| BV (n=4) | Tie | Identical gate counts |
| Clifford (n=4, median of 5 seeds) | **Qiskit** (18% lower) | Qiskit 1.17x vs SuperstaQ 1.43x |

**Qiskit-only finding at n=8 (no SuperstaQ data):** With 5 random ER graph seeds,
the Qiskit ER median is 3.47x (IQR 3.21-3.54x), which sits slightly above complete
(3.32x). This reversal is reproducible across seeds. The likely reason: SABRE exploits
the regular all-pairs structure of complete graphs to find a good qubit layout on
heavy-hex, while random ER topologies at n=8 do not benefit from that regularity even
though they have fewer edges.

**Compile time:** SuperstaQ is 15-25x slower per circuit (median ~0.7-1.4 s vs
Qiskit ~0.03-0.08 s). This reflects network latency to the SuperstaQ API, not
compiler quality.

**Why SuperstaQ loses on QFT and Clifford (n=4):** Qiskit opt-3 performs aggressive
gate fusion and ECR-native synthesis that compresses QFT's all-pairs controlled-phase
structure. SuperstaQ's CZ decomposition of the same structure produces more gates.
This is a gate-synthesis efficiency difference, not a routing difference. Both
compilers have effective all-to-all access for these small circuits on their respective
targets.

## Methodology

### Which circuits are single-instance vs seed-averaged

**Single-instance (one compilation per n):** QAOA on line, ring, and complete graphs;
QFT; Bernstein-Vazirani. These circuits are fully determined by n and the graph type,
so one compilation is sufficient and results are exact.

**Seed-averaged (5 random instances per n):** Erdos-Renyi (ER) QAOA and random
Clifford circuits. ER graphs are sampled randomly, so a single instance can be
unrepresentative. The benchmark draws 5 independent instances (seeds 0-4), compiles
each separately, and reports the **median** routing_overhead with **25th/75th
percentile (IQR) error bars**. Plots show a shaded band for these families.

### Two-layer aggregation for Qiskit

Qiskit's transpiler is itself randomized: qubit routing depends on a seed passed to
`transpile()`. For each circuit instance, the benchmark runs 3 transpiler seeds and
takes the median before recording a result. So a Qiskit ER QAOA data point at n=8
goes through two aggregation layers: 3 transpiler seeds per graph instance, then 5
graph instances, with the median taken at each layer.

SuperstaQ's compilation is deterministic (no transpiler seed), so only the
graph-instance layer applies. This asymmetry is honest: Qiskit's result is the median
of up to 15 compile attempts per group (3 transpiler seeds x 5 graph instances),
while SuperstaQ's is the median of 5.

### Why `routing_overhead`, not `swap_count`

Both compilers report `swap_count = 0`, which looks wrong but is correct:

- **Qiskit / FakeSherbrooke:** SABRE at opt-3 selects a qubit layout where the
  circuit's edges map to adjacent heavy-hex ECR links. When routing is needed, Qiskit
  absorbs the intermediate SWAP directly into ECR gate synthesis. No explicit `swap`
  gate survives `count_ops()`. The routing cost appears as extra ECR gates in
  `two_q_after`.
- **SuperstaQ / Sqale:** No SWAP insertion, as expected. Overhead comes from CZ
  decomposition of input RZZ gates (one RZZ becomes 2 CZ gates), not from routing.

`routing_overhead = two_q_after / two_q_before` captures both effects in one
comparable number and is the correct metric for this benchmark.

### Data coverage and limitations

The SuperstaQ `cq_sqale_simulator` charges credits per job. The free-tier account was
exhausted partway through the sweep:

- n=4: all 15 circuit instances compiled (including all 5 ER QAOA seeds and all 5
  Clifford seeds)
- n=6: 3 of 15 compiled (QAOA line, ring, complete only; ER seeds and Clifford skipped)
- n=8: 0 of 15 compiled

The Qiskit baseline is complete (45 of 45). The ring-topology advantage finding holds
on the data collected, because ring QAOA is a deterministic circuit and was compiled
at both n=4 and n=6. Conclusions about ER QAOA and Clifford at n >= 6 on the
SuperstaQ side would require additional credits to verify.

A structured benchmark that compiles the same circuits through multiple
quantum compilers — SuperstaQ vs Qiskit's transpiler — and measures the
difference in gate count, routing overhead, and fidelity across hardware
topologies.

**The core question:** When does SuperstaQ + neutral-atom hardware (all-to-all
connectivity via atom shuttling) beat IBM's Qiskit transpiler + heavy-hex
(fixed adjacency, SWAP insertion required for non-adjacent gates)?

**Status: Phases 1–4 complete.** Circuit generators, Qiskit baseline,
SuperstaQ cross-compiler harness, and result analysis are all done and tested.

## Why this is interesting

Neutral-atom platforms like Infleqtion's Sqale can rearrange qubits mid-circuit
("atom shuttling"), making long-range entanglement cheap. SuperstaQ is their
compiler SDK that knows about this topology. On a heavy-hex backend, long-range
two-qubit gates require chains of inserted SWAPs. The benchmarks here are
designed to make that tradeoff visible:

- **QAOA on varying connectivity** — line → ring → complete graph. A complete-graph
  QAOA on 8 qubits has 28 two-qubit gates, all non-local. That is expensive on
  heavy-hex and cheap on neutral-atom.
- **QFT with approximation degree control** — QFT has O(n^2) controlled-phase
  gates spanning the full qubit range. Good for measuring long-range connectivity
  advantage.
- **Bernstein-Vazirani with variable secret** — oracle CX count = Hamming weight
  of secret. Sweeping secret weight controls how much long-range entanglement
  the oracle requires.
- **Random Clifford with depth control** — bounded-depth circuits for stress-testing
  compiler routing without the circuit size growing as O(n^2).

## What's in here

| Module | Purpose |
|---|---|
| `scxb/qaoa.py` | QAOA circuits on 5 graph families parameterized by n and connectivity |
| `scxb/qft.py` | QFT with approximation degree and decomposition control |

## Quick example

```python
from scxb import make_circuit, available_families

# List available families
print(available_families())  # ['qaoa', 'qft', 'bv', 'clifford']

# QAOA on a complete graph — worst case for fixed topologies
spec = make_circuit("qaoa", n=6, graph="complete", p=1)
print(spec.circuit.count_ops())  # {'h': 6, 'rzz': 15, 'rx': 6}

# QFT — high-level block vs decomposed
spec_block = make_circuit("qft", n=4, decomposed=False)
spec_elem  = make_circuit("qft", n=4, decomposed=True)

# BV with sparse oracle (2 CX gates)
spec = make_circuit("bv", n=5, secret=0b0011)
print(spec.circuit.count_ops().get("cx"))  # 2

# Clifford with controlled depth
spec = make_circuit("clifford", n=4, depth=20)
```

## Test

```powershell
pytest
```

The suite covers:
- Exact edge counts for line, ring, and complete QAOA graphs.
- RZZ gate count = edges × p for deterministic topologies.
- QFT gate count reduction under approximation; block vs decomposed distinction.
- BV: CX count = Hamming weight of secret, valid range enforcement, default
  behavior (all-ones = max oracle), random secret always nonzero.
- Clifford: full random (reproducible by seed) and depth-controlled mode
  (total gate count exactly equals `depth`).

## Run the cross-compiler benchmark

```powershell
# Both compilers — requires SUPERSTAQ_API_KEY
python -m examples.run_cross_compiler

# Qiskit-only baseline (no API key needed)
python -m examples.run_cross_compiler --no-superstaq

# Fast smoke test
python -m examples.run_cross_compiler --n-values 4 --families qaoa `
    --graphs ring --no-plots --quiet
```

Results land in `results/` as `results.json`, `results.csv`, and PNG plots.
